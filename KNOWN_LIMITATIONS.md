# Known limitations

- This is a runnable foundation with an initial Phase 2 editing workflow, not complete Paint/Photoshop equivalence. Disabled controls identify unfinished functionality.
- `Untitled.paint` was not available. `.paint`, HEIF/HEIC and AVIF are rejected; no Microsoft Paint interoperability is claimed.
- Only Windows in this environment has been built and launched. The CI matrix is configured, not evidence of successful macOS/Linux runs. Windows 10 is not tested here.
- The UI has been compared visually with the provided screenshot but is not pixel-identical. Native title bars vary by OS. The supplied Paint image is 1309 × 962 and displays 100%; Palette defaults to 100% at 1386 × 963, with an added tab strip and third slider.
- Text, additional shapes/brush variants, advanced selections, masks UI, additional blend modes, Gaussian Blur and layer-style dialogs remain pending. Model masks/effects must not be described as finished UI workflows.
- Invert and Brightness are live controls with undo; transactional preview Apply/Cancel and common parameter descriptors are not implemented.
- Strokes and outlined shapes use maximum coverage against pre-stroke pixels, avoiding opacity buildup at joins. No pressure, spacing, tablet-specific input or brush variants yet. Pencil is a one-pixel hard footprint, not a dedicated integer-line rasterizer. Filled ellipses and shape previews still need antialiasing/coverage-preview refinement.
- `.palette` version 1 stores tile byte arrays in compressed JSON. It preserves all currently represented state, not future unimplemented features. Both input and decompressed JSON are capped at 256 MiB. Large/many-layer projects may exceed this sooner than a streamed PNG-asset format would; saving refuses them without overwriting the destination.
- Images are limited to 64 megapixels; raster imports also limit each dimension to 16384. Images exceeding the GPU texture dimension use a reduced display texture while retaining full source/composite data; high-zoom detail on those images needs tiled display textures. This is not a production-scale 8K editor yet.
- History is capped at 256 commands and 128 MiB of uniquely retained backing buffers beyond the current document. Large destructive operations can exceed that budget and lose their undo entry; render textures, live documents, gesture coverage and metadata are outside that budget. Memory/runtime behavior for fully painted 4K/8K multi-document workloads still needs benchmarking.
- The compositor reprocesses the full document after a mutation. Only one render can be queued; stale results are rejected, but running jobs are not cancelled. Rendering is CPU; wgpu currently presents the result.
- No autosave/recovery, recent-files persistence, profile management or Exif/orientation preservation yet. Imports convert to RGBA8, assumed sRGB. Preserve originals when metadata matters.
- GIF imports one frame and exports a still image with palette/transparency limitations. TIFF multi-page behavior, animated WebP and unusual metadata require explicit future notifications. JPEG export uses white for transparency. Ordinary codec tests use small fixtures; they are not a comprehensive conformance/fuzz suite.
- Native dialogs are synchronous modal dialogs; decoding/encoding/rendering run in background workers. Four concurrent file jobs are allowed; further requests report an error.
- Canvas crop/resize changes bounds while retaining hidden source pixels. Painting/movement expands the active source buffer as necessary; masks are reanchored with it. Selection movement previews its boundary and commits pixels on release; a floating pixel preview, feather-aware fractional movement, and affine transforms remain future work.
- Rotations/flips and image resize apply to the entire document, including locked layers. Locks prevent pixel edits on an individual layer. Resize is nearest or premultiplied bilinear; no higher-quality resampling kernels yet. Whole-image transforms reject output planes totaling over 512 MiB; this is an output-buffer policy, not a cap on peak process memory.
- Rectangle/inverted-selection outlines are static black/white contours. Complex selections, marching-ants animation, additive/subtractive selection tools and gesture polish await later milestones and the planned Paint video reference. Large coverage-mask construction/outline caching still happens on the UI thread.
- Fill is contiguous and samples the active source layer in premultiplied RGBA with a per-channel tolerance. It is not a perceptual magic wand or all-visible-layers sampling tool. Live filters may change its displayed colors.
- Clipboard copy/cut samples the active layer's evaluated appearance, not the merged document. Paste creates a raster layer; it does not recover layers from flat clipboard data. Native image-paste events pass through egui's premultiplied ColorImage conversion, which may round low-alpha RGB. Host clipboard ownership/navigation was not destructively exercised during tests; synthetic native paste events and the core RGBA copy/cut/paste paths were tested. Linux/Wayland and macOS clipboard behavior remain untested locally.
- Expensive fills/moves/transforms run one at a time on background snapshots. Results are discarded if their tab changes or closes; obsolete workers finish rather than being interrupted. Canvas painting is temporarily disabled while an edit job runs. Property sliders/text renaming still create commands for individual changes rather than coalescing a full gesture.
- Integer zoom uses nearest sampling. Fractional coordinates are correct, but smooth downsampling, comprehensive DPI and keyboard/screen-reader testing remain pending.
- Distribution installers, macOS app signing/notarization and Linux packages are not produced by this milestone.
